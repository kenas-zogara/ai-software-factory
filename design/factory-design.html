Kenas Software Factory

Design draft · after interview round 3 · 2026-10-16

Kenas Software Factory

One ADO item goes through the spec phase once. Each repo Task then goes through the build phase in its own Orca workspace. You stop the line twice: at the spec gate and at human review.

Swimlane · who does what

The line, end to end

The spec session writes the AC, decisions from calls, the BE dependency and the Figma frames back to the PBI, and its decision log to Obsidian. After the spec gate, the foreman creates one Task per repo with the repo's own skill. Each Task gets one workspace, one draft PR and one worker.

State machine · one PR

What the board shows, and when it moves

The board is ~/.claude/factory/board.html, which sync.py renders every 5 minutes, not Orca's. Spec work has four columns there: to grill, grilling, awaiting approval (your approval queue) and ready to build. The board started view only. Since round 7 it carries actions (see Board actions), which are links the local factory-orca:// handler runs. An open PR, draft or not, is in human review. ADO Testing means merged to dev. AI review is set live by the session running the review. Nothing stores the column. Sync derives it from the ADO state and the PR (draft, eval comment, ready, merged) and writes it to Orca. A new commit after the eval moves the PR back to building, so the ready gate always sees a fresh review.

Round 7 · 2026-10-16

Board actions

The board stops being view only. Each button is a factory-orca://<action>?… link. Factory Orca Link.app runs it through open-orca.sh, then starts a sync so the card moves within seconds. No server is involved. A button that changes ADO state or deletes a workspace asks with confirm() first.

CardButtonsWhat a click does
Awaiting approvalApprovefactory.py approve <id>, after a confirm
ApprovedStartfactory.py start <id> after a confirm, then focuses the new build workspace
My PR (Building, Human review)AI review · e2e reviewA fresh agent terminal in the PR's workspace, or a new workspace on the PR head if none exists. It posts on its own
Reviews laneAI review · e2e reviewA new workspace on the PR head. Findings wait in the session for your OK
Any card with a workspaceOpen · RemoveRemove runs orca worktree rm after a confirm. It's refused while the workspace has uncommitted or unpushed work
Card with no workspace (Build, Reviews)HideAdds the card to hidden.json. It comes back on a new commit or a new review request

A button whose review is already running opens that session instead of starting a second one. A workspace you delete by hand in Orca leaves the board at the next sync.

Reviews lane · other people's PRs

It lists PRs where your review is requested, plus any PR you've opened a review workspace for. The Build lane is unchanged.

ColumnDerived from
To reviewReview requested, or a workspace exists, and nothing is running
AI reviewingThe live marker of an AI or e2e review session
Findings readyThe session finished, and its findings wait for your OK in the session
ReviewedYour submitted GitHub review is newer than the PR's last commit. A new commit sends the card back to To review

Merged or closed PRs leave the lane. My PRs keep AI review as a live-only state and gain an eval ✓ flag while an eval comment is newer than the last commit.

e2e review

An AI review, plus e2e-audit for the specs this diff affects, those Playwright specs, qa-test on the changed behaviour, and ui-ux-test when UI files changed. It runs against the workspace's own dev server on its port band, pointed at the dev API, and covers every app the diff touches. Missing coverage is reported. New specs are not written, because they're the PR author's job.

Hidden cards

Each of the Build and Reviews lanes gets a Show hidden (n) toggle in its header. It's off by default, and the page remembers it per lane. A hidden card that is shown keeps its column but reads as set aside:

Hidden · shown by the toggle

feat(flex-admin): bulk worker export

Unhide

A hidden card has a dashed border, a muted fill and title, and is dimmed to 72%. It carries a hidden <age> chip and offers only Unhide. Lanes count only visible cards. Hidden state lives in ~/.claude/factory/hidden.json, keyed by PR URL, with the head commit and review-request time it was hidden at. Sync shows the card again once either one changes.

Build order

Each step works by itself

  • 1. Hooks: SubagentStart injects kenas-mode, PreToolUse guards Agent to kenas roles
  • 2. factory skill: grill and approve, vault worktree, spec-gate check
  • 3. start: Task, AB# claim lock, workspace, draft PR, brief, and the gh pr create guard. Then a real ticket
  • 4. Ready-gate hook on gh pr ready
  • 5. sync script and its schedule
  • 6. Merge metrics
  • 7. Board actions: link handler, Approve and Start
  • 8. Reviews lane, AI review button, eval ✓ flag
  • 9. e2e review button
  • 10. Remove, Hide, the Show-hidden toggle and the hidden-card style
  • 11. Findings-ready notification: dropped for now. Action results go to actions.log

Settled in round 4

Orca and the foreman

  • Orca is used as it is, through its CLI. No fork. A concrete gap goes upstream as a PR.
  • The foreman is a factory command you run (grill, approve, start, sync), plus a scheduled sync that catches what happens without you.
  • The spec session runs in a per-PBI worktree of the flexii_documents vault, so it shows in the spec column and writes the decision log where it runs.
